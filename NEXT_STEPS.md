## 1. Задача и принятые решения

Старая версия (2.5D на canvas, папки `src/`, `scripts/render.mjs`) не принята: конечности не соединены
друг с другом, картинка плоская, слабый фон и фейерверки. Решения заказчика:

* Настоящее 3D в Blender. Можно переделать всё полностью, суть ролика та же (см.
  `docs/TECHNICAL_SPECIFICATION_VANKING.UZ.txt`).
* Одна панорама на три экрана. Порядок слева направо: **6864 | 11752 | 6240**, высота 1872,
  вся панорама 24856×1872.
* Слева эмо-танцор (Tecktonik), в центре певец, справа саксофонист.
* Конечности должны быть соединены, анимация конечностей должна быть нормальной.
* Финальный рендер заказчик делает сам на Mac (Apple Silicon). Ему нужны готовые команды, включая
  клонирование репозитория.
* Звук не меняется: `deliverables/soundtrack.wav` (15 с, 48 кГц). 30 кадров/с, ровно 450 кадров,
  бесшовный цикл 15 с.

## 2. Как устроен новый пайплайн

Описание — в `blender/README.md`. Коротко: сцена строится кодом Python при каждом запуске, файлов
`.blend` нет. Каждый кадр — чистая функция времени `t`, поэтому цикл замыкается точно, а кадры можно
рендерить в любом порядке и продолжать после остановки. Три экрана — три окна одной камеры (сдвиг
объектива), поэтому картинка непрерывна на стыках.

Запуск в песочнице (Blender 4.5.16 LTS лежал в `/code/tools/blender45/blender`; в новой сессии его
может не быть — `scripts/show.sh setup` скачает его в `tools/`):

```bash
# один кадр панорамы в 1/8 размера
blender -b --factory-startup --python blender/render.py -- --slice pano --scale 0.125 --time 2.5 --out out/peek --samples 8
# крупный план одного персонажа: singer | sax | emo
blender -b --factory-startup --python blender/render.py -- --slice singer --scale 0.5 --time 2.5 --out out/peek
# лист поз одного персонажа на нейтральном свете (быстро, без окружения)
blender -b --factory-startup --python blender/dev/pose_sheet.py -- singer out/poses rest,up,squat,kick,mic,hat front,three,side
# проверка хореографии числами (без Blender)
cd blender && python3 dev/check_choreo.py
```

Модули сцены можно отключать: `--skip environment,lighting,fireworks,characters`.

## 5. Команды для Mac (черновик, не проверено)

Репозиторий закрытый: для `git clone` нужна авторизация GitHub (например `gh auth login`).

```bash
git clone --branch vorflux/blender-3d-rework https://github.com/asintiko/Video1s.git
cd Video1s
brew install ffmpeg
scripts/show.sh setup      # скачивает Blender 4.5.16 LTS (arm64) в tools/, не трогает /Applications
scripts/show.sh test       # три пробных кадра в 1/4 размера -> out/test/
scripts/show.sh final      # полные кадры трёх экранов + mp4 со звуком -> deliverables/
```

Рендер можно прервать (Ctrl-C) и запустить ту же команду снова: готовые кадры пропускаются.
`JOBS=2 scripts/show.sh final` запускает два процесса Blender. Blender через `brew install --cask
blender` ставить не нужно: версия может отличаться.

## 6. Правила, которые нельзя нарушать

* Никакого композитора, bloom, screen-space эффектов (SSS, SSR, преломление) и объёмного тумана: они
  зависят от границ кадра и дадут разную картинку на соседних экранах. Свечение — геометрия с
  аддитивным материалом.
* Всё, что движется, — периодическая функция с периодом 15 с. Никакой физики, симуляций и состояния
  между кадрами. Шейдеры берут время из группы узлов `VK_Time` (`util.time_node`).
* Положение камеры одинаково для всех срезов. Меняются только сдвиг объектива и разрешение.
* Контракты между модулями: `rig.HEAD` (точки головы), `propspec.py` (микрофон, саксофон),
  `pose(t) -> rig.Pose` в хореографии, `extra_bones / build / update` в `mole.py`. Менять только
  согласованно с обеих сторон.
* Каждое изменение сразу коммитить и пушить.
